## Deletion rules verified

| Record category           | Verified behavior                                                                                                                                                                                                                                                                 |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Seven master types        | Admin/owner delete unreferenced users, customers, territories, suppliers, materials, products and prices; product's unused finished item and user credentials are cleaned up. Before/after audit contains no credential password.                                                 |
| Stock drafts              | Opening, purchase and adjustment drafts can be deleted without stock movements. Deleted request keys return 410 on stale creation replay.                                                                                                                                         |
| Production drafts         | Delete input/run/document together before posting and only without overhead events. Overhead-bearing runs are retained.                                                                                                                                                           |
| Submitted orders          | Delete before review, without stock deduction; stale submission replay is rejected.                                                                                                                                                                                               |
| Referenced/posted records | Foreign-key conflicts roll back all changes. Reviewed orders, posted stock/production, invoice snapshots, payments/allocations, credits, overheads, published BOMs, ledger and audit remain protected. Listed protected financial rows have disabled Delete controls and reasons. |
| Concurrency and identity  | Duplicate delete produces one tombstone/audit event; posting versus deletion has one atomic winner; no orphan movements/partial stock. Self/last-admin deletion, forged/stale privileged roles and restricted-role deletion are rejected.                                         |

Physical deletion of posted history would contradict the assessment's audit and immutable-ledger requirements. Use reasoned stock corrections or the existing eligible full-credit workflow. A full credit does not reverse physical dispatch, and paid-invoice refunds are not implemented. Reports/dashboard are derived views, not independently deletable records.

## Remaining limitations and release decision

- New category packs require approved prices, tax/HSN settings and separate published recipes before operational use. Their presence/images do not imply those business values were supplied by the assessment.
- The unresolved Picomatch repeated-extglob denial-of-service advisory **GHSA-fc5q-39xc-vjpf** remains: installed npm copies 2.3.2/4.0.7 and an unversioned Next bundled matcher. The README retains affected paths, reproduced bounded denial-of-service behavior, current reachability assessment and mitigations. No patched release was available in the completed security review; this change does not claim remediation. No forced upgrades or suppressed audit results were used.
- **Public production deployment remains blocked.** Services remain local on loopback. Passing functionality does not approve security/statutory compliance.
- Offline sync, batch/expiry, production planning, GPS, Tamil UI and Tally export remain preferred/optional omissions. Partial dispatch, refunds, physical returns, explicit revaluation and production credential/bootstrap work remain unavailable as documented in README.
- A public repository link, actual remote CI result and recorded assessment video remain manual submission tasks. No remote is configured; no push, email, upload or public hosting was performed.

The local Docker app is synchronized with the updated source and product catalogue. Test screenshots remain in ignored `test-results/`; generated original images and dependency experiments remain outside the repository. No deletion restriction was bypassed.
